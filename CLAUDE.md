# CLAUDE.md — règles du projet « RFP pas envie de travailler » (package backend : `merlin`)

## Source de vérité des données
- `catalog/fabric_catalog.md` (lisible) et `catalog/fabric_schema.csv` (machine) décrivent **toutes** les tables Fabric connues.
- **Ne jamais deviner un nom de table ou de colonne.** Si une colonne n'existe pas dans le catalogue, elle n'existe pas. Demander à l'équipe plutôt qu'inventer.
- Tout ce qui est déduit (clés, relations, sens métier) est marqué « À CONFIRMER » dans le catalogue : ne pas le présenter comme certain.
- Le backend valide les requêtes SQL des automatisations `fabric` contre `fabric_schema.csv` au démarrage (`merlin/data/catalog.py`). Une requête qui cite une colonne inconnue est refusée.
- Si le schéma évolue : remplacer `fabric_schema.csv` par un nouvel export `INFORMATION_SCHEMA.COLUMNS` (mêmes en-têtes) puis mettre à jour `fabric_catalog.md`.

## Architecture (rappel)
- `backend/merlin` : FastAPI. Accès aux données **uniquement** via `merlin.data.access.DataAccess` (jamais de connexion Fabric directe dans un module).
- `automations/<id>/` : un plugin = `manifest.yaml` (+ `run.py` exposant `run(ctx, **params)` pour le type `python`, ou `query.sql` pour le type `fabric`).
- Les jobs tournent dans des threads (`MERLIN_JOB_EXECUTOR=process` pour des processus séparés, `merlin/jobs`). Logs et statut diffusés en SSE.
- Modules : `merlin/rfi` (remplissage RFI Excel/Word ; ontologie `rfi/ontology/*.yaml` validée contre le catalogue ; méthode : `docs/COMPLETEUR_RFI.md` ; toute évolution doit garder 100 % de précision automatique sur `tests/rfi_gold.yaml` et `tests/rfi_gold_es_it.yaml` ; questions es / it lues via le lexique pivot `rfi/lexicon.py` + `ontology/lexicon.yaml` ; plusieurs ISIN : grille par part ou une section par ISIN, chaque case lit sa part), `merlin/rfi/precedents` (anciens RFI comparés à Fabric, SQLite FTS5 sous `data/rfi/`, jamais committé ; `auto_copy_allowed` toujours faux), `merlin/rfi/sources` (SharePoint : Graph ou dossier synchronisé, lecture seule ; synchronisation complète en arrière-plan `sync.py` : incrémentale, reprise, relances des erreurs passagères, chemins longs, clé = chemin complet), `merlin/rfi/documents` (DIC PRIIPs / prospectus : site public, cache `data/rfi/documents/`, lecture sans IA, recoupement avec Fabric), liaisons apprises `merlin/rfi/precedents/bindings.py` (`data/rfi/bindings.json`, jamais committé), `merlin/rfi/copilot.py` (Copilot M365 : prompt à copier avec format de retour imposé, réponse collée lue et contrôlée ; pack Excel en option ; toujours « à vérifier », source citée obligatoire), `merlin/fundshop` (documents du site sans navigateur : adresse directe `{PRÉFIXE}_{GUID}_{LANGUE}_{PAYS}.pdf`, réseau Python puis connexion Windows `net.py`, mémoire `data/fundshop/`, lien collé « J'ai le lien », ISIN vérifié dans chaque PDF, chaque échec expliqué via `problems.py`, liste vierge Excel `template.py`), `merlin/omni` (OMNI mensuel : Holdings Fabric à la vraie date d'inventaire, performances dossier puis Outlook, contrôles relatifs ; méthode : `docs/OMNI_ET_DOCUMENTS.md`), `merlin/qvidian` (services web SOAP Qvidian, opérations confirmées par le WSDL et les exemples du paquet `qpa_Oct26_consolidated` ; instantané `data/qvidian/` jamais committé, démo et réel jamais mélangés ; méthode et capacités confirmées / manquantes : `docs/QVIDIAN.md`), `merlin/search` (moteur de recherche générique : BM25F + RM3 + thésaurus métier + n-grammes, vecteurs E5 et reranker ONNX facultatifs dans `data/models/`, fusion RRF ; - `backend/vendor/` : code repris **tel quel** (bot merge codes, tryv2). Ne pas le modifier ; adapter dans `merlin/` à la place.
- Connexion Fabric : `merlin/data/fabric_link.py` (mssql-python, `ActiveDirectoryInteractive`, une seule connexion partagée ; jobs en threads par défaut).
- Front : version de base « RFP pas envie de travailler » (cartoon) ; l'Atelier Excel s'appelle **Merlin** (navigation) et porte la fiche fonds `/atelier/fonds/:isin` (Product Info + JUMP, API `/api/atelier/fund-sheet`). Section Qvidian = **QviAPI**, seule partie sombre « salle des machines » : `html[data-section="qviapi"]` posé par `QvidianSection`, styles `styles/qviapi.css` (mêmes variables, autres valeurs ; Space Grotesk / DM Sans), composants `components/qviapi/` (clavier 3D de la Recherche + jauges de liquide des moteurs = part réelle des 10 premiers résultats par moteur, constellation 3D du Cockpit, cadrans) ; 3D jamais affichée en mouvement réduit ni sans WebGL. - `frontend/` : React + Vite + TS. `frontend/dist` est committé (le lanceur `run.bat` n'a pas besoin de Node) : relancer `npm run build` après toute modification du front. Textes de l'interface centralisés dans `src/content/texts.ts`, tokens de motion dans `src/motion/tokens.ts`, tokens visuels dans `src/styles/tokens.css`.

## Règles
- Aucun secret dans le code : variables d'environnement (voir `.env.example`).
- Aucune donnée réelle dans les exemples, mocks ou tests (ISIN fictifs préfixés `QZ`, fonds imaginaires).
- Les fichiers Excel déposés dans l'Atelier ne sont **jamais** modifiés : chaque exécution écrit une nouvelle version.
- Idem pour les RFI : le document rendu doit rester identique à l'original hormis les cellules de réponse (test `test_modules.py`).
- Documents téléchargés et fichiers OMNI : jamais écrasés sans demande explicite (écriture atomique).
- Qvidian : lecture seule par défaut ; aucune écriture sans prévisualisation et mot de passe d'équipe (`QVIDIAN_WRITE_PASSWORD`, .env seulement) ; jamais de création ni de suppression de contenu. Les écritures ne sont jamais relancées automatiquement. La section front vit sous `/qvidian/*` (`frontend/src/pages/qvidian/`).
- Modèles de recherche : jamais téléchargés sans clic explicite ; jamais installés sans vérification de la taille et du SHA-256 ; `data/models/` n'est jamais committé. Le sens seul (E5) ne suffit jamais à dire que deux questions de RFI sont la même : toujours vérifier par le concept de l'ontologie.
- Qvidian : clé d'API saisie dans l'app (Connexion) et mémorisée sur le poste (`data/qvidian/credentials.json`, chiffrée DPAPI, jamais renvoyée au navigateur ni journalisée), ou `QVIDIAN_USER` + `QVIDIAN_API_KEY` dans `.env` (prioritaire) : connexion automatique au démarrage, reconnexion silencieuse, synchronisation lancée après connexion (pas de SSO).
- Surlignage jaune des réponses à demander : option du téléchargement ; seules les cases réponse et `xl/styles.xml` changent.
- Compléteur RFI : un choix (« Choisir », saisie, Copilot) ne recalcule que la case concernée (cache des cases dans `api/rfi.py`) ; « Analyser » repart de zéro (`fresh`).
- Le référentiel Excel des merge codes (noms de collaborateurs) n'est **jamais** committé : il vit dans `data/mergecodes/`. Idem pour l'inventaire « Qui contacter » (`data/contacts/`).
- SQL des automatisations écrit en dialecte T-SQL (Fabric). En mode mock, il est traduit automatiquement vers SQLite (sqlglot) : rester sur du SQL standard (SELECT, JOIN, GROUP BY, TOP, CTE).
- `prefers-reduced-motion` doit toujours être respecté ; le fun ne bloque jamais une action.
- Les scripts historiques `JUMP_OMNI.py` et `OMNI_MENSUEL.py` (Windows/Excel/Outlook) sont conservés tels quels ; ils ne font pas partie de Merlin.

## Commandes
- Utilisateur : double-clic sur `run.bat` (ou `python run.py`)
- Backend : `cd backend && pip install -r requirements.txt && uvicorn merlin.main:app --reload`
- Tests backend : `cd backend && pytest`
- Frontend : `cd frontend && npm install && npm run dev` (build : `npm run build`)
